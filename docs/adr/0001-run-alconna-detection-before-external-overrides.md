# Run Alconna Detection Before External Overrides

PicMenu Next resolves help data in this order: plugin Metadata, Alconna detection eligibility, external menu config, detected function-item generation, then Mixin. External menu config is a user override layer, so it should see and override automatically detected function items rather than suppressing detection by running before it; if an external config omits `funcs`, detected function items remain, and if it declares `funcs`, that list replaces them as a whole rather than merging item by item. The same explicit-list rule applies to plugin Metadata: `menu_data = []` means the plugin intentionally declares an empty function item list, while omitted or `None` `menu_data` leaves room for automatic detection. An explicit external `funcs` list also takes precedence over Metadata `alc_force_enable_detect`, so forced detection does not add detected function items back after the user has replaced the list. External menu config may override presentation policy such as Markdown rendering, so detected function items are generated after external overrides and match the final Markdown policy, but it does not expose `alc_force_enable_detect`, because detection policy belongs to plugin Metadata rather than the user override layer.

Implementation should use Pydantic fields-set state to distinguish omitted external fields from explicitly declared external fields instead of introducing a separate Alconna detection policy model. External menu config should use a dedicated PicMenu extension config model that omits `alc_force_enable_detect`, so validation and generated schema do not expose a detection-policy field in the user override layer. External config model defaults must not overwrite Metadata values unless the corresponding field was explicitly set. Nested external `pmn` overrides only the fields explicitly set inside that object; `pmn = {}` is a no-op rather than a reset to defaults. External `pmn` may be omitted or provided as an object, but `pmn = null` is not accepted; external `funcs` may be omitted or provided as a list, but `funcs = null` is not accepted. Because external `funcs` replaces the whole function item list, each item in that list must be a complete function item rather than a patch-style optional item; `OptionalPMDataItem` remains scoped to Alconna command overrides.
